Data Acquisition Interface

A standalone Python application developed for Los Alamos National Laboratory to automate the configuration of experimental data acquisition equipment, replacing a manual LabVIEW-based workflow with a faster and more streamlined interface.

Overview

Setting up equipment for experiments can require manually configuring multiple oscilloscopes, which takes time and leaves room for human error. Our project aims to simplify this process by providing a single application that can detect connected devices and automatically configure them using experiment configuration files.

Developed for Los Alamos National Laboratory (LANL) as part of a three-person capstone team, the application uses Python, PyQt5, PyVISA, NumPy, and SCPI commands to communicate with laboratory equipment over USB and Ethernet.

As team CTO, I led the technical direction of the project, managed our GitHub workflow, and helped coordinate development and integration. My main contributions included implementing configuration file loading, persistent device names, applications logging, and packaging the application into a standalone executable.

Requirements / Scope

The overal goal was to create a reliable, standalone application that could simplify equipment setup and reduce the amount of manual configuration required before experiments while keeping the primary export formats used for data analysis.

Key requirements included:

  • Device Discovery: Automatically detect connected oscilloscopes through USB and Ethernet connections.
  • Device Status Monitoring: Display connected devices and their configuration status through a central interface.
  • Configuration File Support: Load experiment configuration files provided by LANL and apply their settings to connected equipment.
  • Automated Configuration: Use PyVISA and SCPI commands to automatically configure multiple connected devices at once based on the loaded configuration files.
  • Device Management: Allow users to assign friendly names to devices and retain those names between application sessions.
  • Logging: Record application actions, warnings, errors, and exceptions with daily granularity.
  • Data Export: Support exporting data into CSV and NUM-DAT formats at any time.
  • Standalone Deployment: Package the application into an executable that can run locally withotu requiring an external network connection.
